# Contributing

Thanks for helping. These extensions run inside GNOME Shell and patch parts of it, so small, careful changes
with a clean `disable()` are what matter most.

## Ground rules

- **English in code**: identifiers, comments, log lines and file names.
- **No language is hardcoded.** No keyword or regex that detects intent, tone or content in one human language; no
  length limit calibrated on one script; no assumption about number, date or name formats. User-visible strings go
  through gettext (`import {gettext as _} from 'resource:///org/gnome/shell/extensions/extension.js'`), and
  must survive non-Latin scripts and right-to-left text. Currently no extension has a UI string; adding one
  means adding `po/` (see below).
- **`disable()` undoes everything `enable()` did**: signal connections, GLib sources, timelines, actors, effects,
  patched prototype methods, blocked handlers. Prefer the helpers (`Replacements` in `motion/utils.js`,
  `stopAll()` of the toolkit).
- **Fix causes, not symptoms**: no retry loop hiding a failure, no empty `catch`. A `catch` that ignores an error
  needs a comment saying why it is harmless; otherwise log with `console.error`.
- Follow the [extensions.gnome.org review guidelines](https://gjs.guide/extensions/review-guidelines/review-guidelines.html):
  no unnecessary subprocesses, no synchronous file I/O in hot paths, no minified code, import style
  `resource:///org/gnome/shell/...`.
- **Source files stay under 500 lines.** Split along a real seam (module, concern), never at an arbitrary line.
  Generated and vendored data are exempt.
- Never set a negative margin on an `St.Icon`: it crashes the Shell.

## Workflow

```sh
npm ci
tests/run.sh            # must pass
scripts/install.sh --dest /tmp/ext-test   # try an install without touching your session
```

- `shared/m3e/` is the single source of truth of the toolkit; never edit the embedded `extensions/*/m3e/` copies
  (git-ignored build products, created by `scripts/build.sh`).
- `shared/m3e/tokens.js`, `shared/generated/` are generated by `python3 tools/generate.py`; edit the sources in
  `shared/data/` and regenerate. CI fails if the committed outputs are stale.
- Add or update the unit tests under `tests/unit/` for pure logic. Code that needs a running Shell is covered by the
  nested bench in `tests/bench/`.
- Nested shells: headless, virtual monitor, named Wayland socket, private `XDG_RUNTIME_DIR`, `XDG_*` exported before
  `dbus-run-session`. Never touch your real `wayland-0` or dconf. Do not run `unittest discover` on benches that open
  windows.
- Update `CHANGELOG.md`.

## Translations

Run `xgettext` over the extension sources into `extensions/<uuid>/po/<domain>.pot`, add `<lang>.po` files, and set
`gettext-domain` in `metadata.json` (already set). `scripts/install.sh` and `scripts/pack.sh` compile `po/`
automatically.

## Reporting bugs

Use the issue templates. Include `gnome-shell --version`, session type, the theme version, and the relevant Shell log.
