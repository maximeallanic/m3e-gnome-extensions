# shared/m3e — the M3E motion toolkit

Single source of truth of the motion engine used by `m3e-motion` and `m3e-extensions`.
`scripts/build.sh` copies this directory into `extensions/<name>/m3e/` (each extension embeds its own copy,
because a Shell extension cannot import from another extension). Do not edit the embedded copies.

Everything runs inside GNOME Shell (GJS 1.88, Shell 50: St / Clutter / Cogl / Shell). `spring.js`, `curve.js`
and `tokens.js` import nothing from GI and are unit-tested headless.

| File | Role |
|---|---|
| `tokens.js` | Generated by `tools/generate.py` (never edited): `SPRINGS`, `THRESHOLDS`, `PATTERNS`, `CURVES`, `ANDROID` |
| `spring.js` | Pure spring engine (port of Compose `SpringSimulation` / `SpringEstimation`) |
| `curve.js` | Pure fixed-duration cubic curves (Android `PathInterpolator`) |
| `track.js` | One animated property of one actor (a `Clutter.Timeline` writing every frame) |
| `animate.js` | Registry + `Animation` + public API (`animate`, `release`, `stopAll`…) |
| `corners.js` | `RoundedCorners` `Shell.GLSLEffect` (animatable corner radius and clip rectangle) |
| `pattern.js` | Common machinery of transition patterns (master travel, windows, take-over) |
| `container.js` | Container transform (+ Android app-launch variant) |
| `patterns.js` | Entry point of the pattern catalogue: shared axis, fade through, fade, morph corners, re-exports |

**Why a custom spring engine** (searched before building): `Adw.SpringAnimation` lives in libadwaita, which
is a GTK widget library not loaded in the Shell process (the Shell is St/Clutter); Clutter only offers
duration/progress-mode timelines (`Clutter.Timeline`, `ease()`), no physical spring, and its
`set_progress_func` return value is lost under GJS 1.88 (see `animate.js`). No maintained GJS spring
library exists, and the Compose spring maths (the M3 Expressive reference) is ~100 lines, so it is ported
and verified against a Python port (`tests/unit`).

Threads of design that every consumer must know:

* One driver: every animated property gets its own `Clutter.Timeline` attached to the actor (so to the clock
  of its monitor); on each `new-frame` the value `target + state(spring, x0, v0, t).x` is written.
* A property has one owner: a new `animate()` on the same property of the same actor takes it over
  (retargeting, keeping position and velocity).
* `stopAll()` is the single entry point of an extension's `disable()`: it stops every pattern then every
  animation of **this copy** of the toolkit, without calling any `onDone`.
* GType names of `RoundedCorners` / pattern driver are made unique per embedded copy from `import.meta.url`.
* Logging is `console.error(...)`; callbacks supplied by callers (`onDone`) that throw are logged, never
  swallowed silently and never allowed to break the animation machinery.

## Public API

### `animate.js`

```js
animate(actor, targets, {spring, delay, onDone, threshold} = {}) → Animation
release(actor, prop, target, velocity, spring, {threshold, onDone} = {}) → Animation
currentState(actor, prop) → {value, velocity} | null
stopAll()
virtualProperty(actor, name, {read, write}) → '@v.<name>'
removeProperty(actor, name)
```

* `targets`: `{property: value}`. Property keys: any numeric actor property (`'translation_x'`, `'scale_x'`,
  `'opacity'`, `'x'`…; dashes are normalised to underscores), colour properties (`*_color`, value is a string
  or `Cogl.Color`, blended through a bounded progress), effect properties `'@effects.<effect-name>.<prop>'`,
  virtual properties `'@v.<name>'` (see `virtualProperty`).
* `spring`: a name of `SPRINGS` (`'DefaultSpatial'`, `'FastEffects'`, `'ComposeSpringDefault'`…); a family
  `'Default' | 'Fast' | 'Slow'` (completed to `…Spatial` or `…Effects` per property, colours and opacity use
  Effects); `{stiffness, damping}`; a fixed-duration motion `{curve, duration}` (`curve` = a name of `CURVES`
  or `{segments}`, `duration` in ms); or a per-property table `{opacity: 'FastEffects', scale_x: 'FastSpatial'}`.
* `delay`: ms of real time before the property starts. `threshold`: rest threshold in the property's unit
  (number, or `{prop: n}`); default 0.5 px, 0.01 for scales/colours, 0.1 degree, 2.55 for opacity.
* `onDone()`: called once, when every property of the animation has settled (also in the next idle when every
  value was written immediately); not called when the animation is stopped, taken over or its actor destroyed.
* `Animation`: `running` (getter), `retarget(targets, delay = 0)`, `stop()` (in place, no `onDone`),
  `finish()` (jump to the end and call `onDone`), `timing(prop)` → `{elapsed, duration, done}` (real ms).
* `release` = end of a gesture: starts from the current value with the finger velocity (units/second).
* Test seams (leading underscore, used by tests and the bench): `_springFor(prop, spring)` (was `_ressortDe`),
  `_thresholdFor(prop)` (was `_seuilDe`), `_plan(current, velocity, target, spring, threshold)` →
  `{driver: 'frame' | 'none', x0, v0, durationMs}` (was `_planifier`), `_registerStop(callback)`
  (was `_inscrireArret`), `_diagnostic()` → `{actors, tracks, pendingDone}`.

### `spring.js` (pure)

```js
state(spring, x0, v0, tMs) → {x, v}          // displacement to rest (final position 0) and velocity (units/s)
duration(spring, x0, v0, threshold) → ms     // integer ms for |x| to stay under threshold (0 under threshold)
progress(spring, x0, v0, tMs) → 1 - x/x0     // 0 at start, 1 at rest; 1 if x0 = 0
```

`spring` = name of `SPRINGS` or `{stiffness, damping}` (mass 1).

### `curve.js` (pure)

```js
resolveCurve(curve) → {segments}
value(curve, x) → y          // x clamped to [0, 1]
slope(curve, x) → dy/dx
curveState({curve, duration}, x0, tMs) → {x, v}   // like state() for fixed-duration motions
isCurve(motion) → boolean
```

### `corners.js`

```js
corners(actor) → RoundedCorners         // named effect 'm3e-corners', added if missing
CORNERS_EFFECT_NAME = 'm3e-corners'
expectedTexture(actor) → [w, h]         // size Mutter will give the off-screen texture (was texturePrevue)
class RoundedCorners extends Shell.GLSLEffect
```

`RoundedCorners` GObject properties (all animatable as `'@effects.m3e-corners.<prop>'`): `radius`, `left`,
`top`, `width`, `height` (logical px local to the actor; `width`/`height` < 0 means the whole actor),
`compensate` (boolean: radius expressed in on-screen px despite the actor's own scale). Bench diagnostic:
`effect._diagnostic()`.

### `patterns.js` / `pattern.js` / `container.js`

```js
containerTransform(source, destination, {sourceRadius, destinationRadius, hideSource = true,
                   keepCorners = false, content = null, reverse = false, launch = null, onDone}) → Pattern
sharedAxis(outgoing, incoming, axis /* 'x'|'y'|'z' */, direction /* 1|-1 */, {onDone}) → Pattern
fadeThrough(outgoing, incoming, {onDone}) → Pattern
fade(actor, entering, {origin: {x, y}, pivot: {x, y}, onDone}) → Pattern
morphCorners(actor, radius, {spring, onDone}) → Pattern
windowProgress(p, {start, end}, spring = null) → [0, 1]     // pure; also exported from patterns.js
```

* `source` of `containerTransform` is an actor (cloned, then hidden) or a plain rectangle
  `{x, y, width, height}` (scene px); it may carry a numeric `radius` used as the default `sourceRadius`
  (was `rayon`). `content` is `{x, y, width, height}` local to `destination` (was `{x, y, l, h}`).
* `launch` = `{motion: {curve, duration}, opacity: {curve, duration, delay}}` (Android app-launch variant).
* `Pattern`: `target('end' | 'start', {onDone})` (new segment from the current state; `onDone` replaces the
  pattern's callback for this and later segments), `stop()`, `finish()`, `timing()` → `{elapsed, duration, done}`,
  `running`. Every factory starts toward `'end'` and returns the `Pattern`.
* Pattern classes from `pattern.js` (for building new patterns): `Pattern`, `windowProgress`, `opacityWindow`,
  `isMoving`, `setPivot`, `linear`, `mix`, `edgeGap`, `rectEdges`, `CENTER`, `ORIGIN`, `_diagnosticPatterns`.
  `patterns.js` also exposes `_diagnostic()` → `{patterns, owners, hiddenSources}`.

